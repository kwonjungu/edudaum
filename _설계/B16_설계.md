# B16 체험 설계 — 예시를 옮겨 보기

## 0. 만들까 말까

**만든다.**

예시를 바꾸면 거기서 찾은 규칙이 바뀐다는 것은 종이 카드로는 확인할 수 없다.
학생이 규칙을 다시 찾는 데만 몇 분이 들고, 짝마다 결과가 달라 견줄 기준이 없다.
화면은 예시 한 장을 옮기는 즉시 규칙과 새 카드 판정을 다시 내놓는다.

교실에서 하는 일(규칙표로 판정, 스스로 규칙 찾기, 새 카드 판정)을 되풀이하지 않는다.
웹이 맡는 것은 학생이 손으로 할 수 없는 **다시 찾기**뿐이다. 5분 안에 끝나고
설치·서버·외부 호출이 없다.

## 1. 과정안 어디에 붙는가

- 블록 B16 (3~4/32차시), 4차시 **활동3 뒤 · 활동4 앞**.
- 활동3에서 두 방식의 판정을 기록표에 다 적은 뒤에 연다. 활동4의 "예시에서 찾은
  규칙이 치우칠 수 있다"를 쓰기 전에 근거를 눈으로 잡는 자리다.
- 교실에서 **5분**. 실물 카드 활동 뒤에 붙는다.

## 2. 한 문장

예시 카드 한 장을 다른 상자로 옮기면, 기계가 찾아내는 규칙이 바뀌고 새 카드 세 장의
판정도 따라 바뀐다.

## 3. 화면

**1화면.** 스크롤 없이 위에서 아래로 예시 상자 → 찾은 규칙 → 새 카드 판정.

| 보이는 것 | 학생이 하는 것 | 다음 |
|---|---|---|
| 1상자·2상자에 나뉜 예시 카드 4장, 찾은 규칙 한 낱말, 새 카드 3장과 각 카드가 갈 상자 | 예시 카드 하나를 눌러 옆 상자로 옮긴다 | 없음. 같은 화면에서 되풀이한다 |

## 4. 조작과 값

- 조절하는 값은 **예시 카드의 자리 하나**뿐이다. 한 번에 한 장만 옮겨진다.
- 예시 카드 (칠하기 / 크기 / 모양)
  - 가 = 칠함·큼·동그라미 · 나 = 칠함·큼·네모 · 다 = 안칠함·큼·세모 · 라 = 안칠함·작음·동그라미
  - 처음 자리: 가·나는 1상자, 다·라는 2상자
- 새 카드 (판정만 받는다, 옮길 수 없다)
  - 칠함·작음·세모 / 안칠함·큼·네모 / 안칠함·작음·세모
- 기계가 하는 일: 칠하기 → 크기 → 모양 차례로, 두 상자의 값이 **하나도 겹치지 않는**
  첫 특징을 규칙으로 삼는다. 겹치지 않는 특징이 없으면 `못 찾음`, 한 상자가 비면
  `한쪽이 비었어요`.
- 이렇게 바뀐다 (처음 자리 → 한 장 옮김)

| 옮긴 카드 | 찾은 규칙 | 새 카드 판정 |
|---|---|---|
| (처음) | 칠하기 | 1상자 · 2상자 · 2상자 |
| 라 → 1상자 | 모양 | 2상자 · 1상자 · 2상자 (두 장 바뀜) |
| 다 → 1상자 | 크기 | 2상자 · 1상자 · 2상자 |
| 나 → 2상자 | 못 찾음 | 알 수 없음 ×3 |
| 넷 다 한쪽으로 | 한쪽이 비었어요 | 알 수 없음 ×3 |

- 판정이 바뀐 새 카드는 테두리를 굵게 하고 `바뀜`을 띄운다. 바뀌지 않은 카드는 그대로 둔다.

## 5. 글자 (그대로 쓸 문구)

| 자리 | 문구 | 글자 |
|---|---|---|
| 제목 | 예시를 옮겨 보기 | 8 |
| 부제 | 카드를 누르면 옆 상자로 가요 | 15 |
| 라벨 | 예시 카드 / 1상자 / 2상자 / 찾은 규칙 / 새 카드 | 5·3·3·5·4 |
| 규칙 값 | 칠하기 / 크기 / 모양 / 못 찾음 / 한쪽이 비었어요 | 3·2·2·4·8 |
| 판정 값 | 1상자 / 2상자 / 알 수 없음 | 3·3·5 |
| 표시 | 바뀜 | 2 |
| 버튼 | 처음으로 | 4 |
| 관찰 | 무엇을 옮기니 규칙이 달라졌나요? | 17 |
| 관찰 | 한쪽에만 모으면 어떻게 되나요? | 16 |

화면 전체 **109자** (브라우저에서 실제로 센 값).

## 6. 연습 모드

바깥에서 가져오는 것이 없다. 인터넷을 끊어도 같게 열린다. 카메라·마이크를 쓰지 않아
권한을 묻지 않는다. 그러므로 따로 연습 모드를 두지 않았다 — 막힐 것이 없다.

## 7. 만드는 방법

외부 라이브러리 없음. CDN 없음. 바닐라 JS 한 파일. 카드 그림은 인라인 SVG.

```
카드마다 fill/size/shape 세 값을 data-*로 들고 있다
누르면 그 카드를 반대쪽 slot으로 appendChild 한다 (화면을 다시 그리지 않는다)

findRule():
  한쪽 상자가 비면 -> '한쪽이 비었어요'
  [fill, size, shape] 차례로:
     v1 = 1상자의 값 모음, v2 = 2상자의 값 모음
     겹치는 값이 없으면 -> 그 특징을 규칙으로 돌려준다
  끝까지 없으면 -> '못 찾음'

새 카드 판정:
  카드의 그 특징 값이 v1에 있으면 1상자, v2에 있으면 2상자, 둘 다 아니면 알 수 없음
  앞서 적어 둔 판정과 다르면 그 카드에만 '바뀜'을 붙인다
```

`처음으로`는 네 장을 처음 자리로 되돌리고 `바뀜` 표시를 모두 지운다.

## 8. 난이도 점검

| 재는 것 | 상한 | 이 차시 |
|---|---|---|
| 첫 조작까지 | 30초 | 즉시 (카드가 화면 위쪽, 부제 한 줄) |
| 화면 수 | 3 이하 | 1 |
| 한 화면의 조작 요소 | 5 이하 | 5 (카드 4 + 처음으로) |
| 한 번에 바꾸는 값 | 1 | 1 (카드 한 장) |
| 전체 체험 시간 | 5~10분 | 5분 |
| 새로 배우는 조작법 | 0 | 0 (누르기만) |

## 9. 디버깅

공통기준 8-2 점검표에 이 차시에서 더 본 것:

- 카드를 빠르게 여러 번 눌러도 자리가 어긋나지 않는가 (DOM 이동이라 쌓이지 않는다).
- 네 장을 모두 한쪽으로 몰았을 때 `한쪽이 비었어요`가 뜨고 화면이 깨지지 않는가.
- `바뀜` 표시가 바뀐 카드에만 붙고, `처음으로` 뒤에는 사라지는가.
- 카드 버튼에 글자가 없으므로 `aria-label`이 자리(1상자/2상자)까지 알려 주는가.
