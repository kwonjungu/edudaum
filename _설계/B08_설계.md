# B08 체험 설계 — 아홉과 열

2026. 9. 17. 저녁에 **게임으로 다시 짰다.** 앞판(값을 밀면 결과가 보이는 화면)이
재미없다는 것이 드러나서다. 앞판의 까닭은 10절에 남겨 둔다.

## 0. 만들까 말까

**만든다.** 코드 만들기와 실물 버튼 시험(활동2·3)은 그대로 한다.

- **웹이 아니면 못 하는가.** 활동3은 `교사가 준 오류 예제로 같은 두 경우를 다시 시험하기`와
  `오류 예제에서 규칙과 다른 곳이 어디인지 적기`를 시킨다. 오류 예제를 기기로 만들려면
  판마다 블록을 고쳐 다시 전송해야 하고, 한 시간에 한두 판밖에 못 한다.
  화면은 판을 무한히 낸다.
- **값을 바꾸면 결과가 바뀌는가.** 규칙 한 줄이 바뀌면 갈리는 자리가 통째로 옮겨 간다.

**여전히 만들지 않는 것.** 블록 놓기, 전송, 뼈대 파일. 화면에 블록 창을 만들지 않는다.

---

## 1. 게임 — 무엇을 해내야 하나

> **규칙 한 줄을 읽고, 하트와 가위표가 갈리는 자리를 먼저 짚어라.**

판마다 규칙이 둘 중 하나로 나온다. **이 둘이 헷갈리는 것이 이 게임의 전부다.**

| 규칙 | 갈리는 자리 |
|---|---|
| `횟수가 10과 같거나 크면 하트` | **10** |
| `횟수가 10보다 크면 하트` | **11** |

한 글자 차이로 자리가 한 칸 옮겨 간다. 어른도 헷갈린다.
활동3·4가 기준값 **양쪽**을 시험하게 하는 까닭이 바로 이 한 칸이다.

**게임의 뼈대**

| 있어야 하는 것 | 이 화면에서 |
|---|---|
| 목표 | 갈리는 자리를 짚는다 |
| 실패 | 빗나간다. 몇 칸 옆이었는지 나온다 |
| 예상 | **짚기 전에는 시험 버튼이 잠긴다** |
| 제약 | 짚기는 판마다 **한 번**. 무르지 못한다 |
| 되풀이 | `다음 판`마다 규칙과 기준값이 새로 나온다 |

**점수·등수를 세지 않는다.** 몇 판을 맞혔는지도 세지 않는다.
재미는 한 글자에 속았다가 알아채는 그 순간에서 온다.

## 2. 과정안 어디에 붙는가

- 블록 B08, 15~16차시. **16차시 활동3 「기준값 양쪽을 시험하기」 뒤, 활동4 「고치고 나만의 판정 부스 차리기」 앞**에 4~5분.
  활동3 다섯째 줄 `판정 맞히기 놀이: 짝이 부른 횟수로 나올 그림 먼저 말하기`를 여러 판으로 늘린 자리다.
- 활동3의 아홉 번·열 번 시험은 실물 버튼으로 이미 한 뒤다. 그것을 대신하지 않는다.
  오류 예제(거짓 자리에 가위표가 빠진 코드) 시험과 고치기도 기기에서 한다. 화면은 오류 예제를 흉내 내지 않는다.
- 활동4의 `기준값만 10에서 5로 바꾸고 예상을 먼저 적기`를 판마다 기준값이 바뀌는 것으로 미리 겪는다.

## 3. 화면 (1화면)

| 구역 | 보이는 것 | 학생이 하는 것 |
|---|---|---|
| 위 | 이번 판의 규칙 한 줄. 갈림말에 밑줄 | 읽는다 |
| 가운데 | 0~15 띠 열여섯 칸 | **한 칸을 짚는다** |
| 아래 | 5×5 화면, 누른 횟수, 버튼 넷 | 눌러서 시험한다 |

- 시험한 칸에는 하트나 가위표가 **새겨져 남는다.** 지우지 않는다.
- 경계 양쪽(갈리는 칸과 그 앞칸)을 둘 다 시험하면 갈린 자리가 드러난다.
  **화면이 먼저 알려 주지 않는다.** 학생이 양쪽을 다 눌러야 드러난다.
- 짚은 칸은 굵은 테두리, 진짜 칸은 안쪽 테두리. 같으면 둘이 겹친다.

## 4. 조작과 값

- 조절하는 값: **누른 횟수** 하나. 0~15.
- 주된 조작: 띠에서 **한 칸 짚기**(판마다 한 번).
- 버튼: `왼쪽`(값 +1), `오른쪽`(지금 값으로 시험), `다시 시작`(값을 0으로), `다음 판`.
- 기준값은 판마다 **3~13에서 새로 정해진다.** 미리 정해 두지 않는다.
- 규칙은 판마다 두 갈래 가운데 하나가 반반으로 나온다.

**값을 1씩만 올리는 까닭.** 마이크로비트가 그렇다(활동1 그대로). 열두 번을 시험하려면
열두 번 눌러야 한다. 그 품 때문에 **아무 데나 찍어 보지 않고 규칙을 읽게 된다.**
품이 곧 제약이다.

**열어 두는 딴짓.** 짚어 놓고 열여섯 칸을 모두 시험해 볼 수 있다. 막지 않는다.
띠가 하트와 가위표로 반씩 차는 것을 보는 것도 활동2의 규칙 그대로다.

## 7. 만드는 방법

```
새판():
  n  = 3~13 가운데 하나
  ge = 참·거짓 반반
  edge = ge ? n : n + 1          // 실제로 갈리는 자리
  값=0, 짚음=null, 드러남=거짓, 시험한칸 = 열여섯 개 null
  규칙줄 = ge ? '횟수가 n(과|와) 같거나 크면 하트' : '횟수가 n보다 크면 하트'

짚기(v): if (짚음 !== null || 시험한 칸이 하나라도 있으면) 아무 일도 하지 않는다
         짚음 = v

오른쪽(): if (짚음 === null) return          // 짚기 전에는 시험하지 않는다
  결과 = (ge ? 값 >= n : 값 > n) ? '하트' : '가위표'
  시험한칸[값] = 결과
  if (시험한칸[edge-1] === '가위표' && 시험한칸[edge] === '하트') 드러남 = 참
```

- 기준값이 3~13이므로 `edge`는 3~14다. 0이 되는 일이 없어 그 분기를 두지 않는다.
- 띠 열여섯 칸과 LED 스물다섯 칸은 JS로 한 번만 만들고 그 뒤엔 속만 바꾼다.
  띠 칸을 `<button>`으로 두는 것은 진짜 눌러야 하기 때문이다. `role="button"`을 쓰지 않는다.
- 하트·가위표는 인라인 SVG. 색으로만 구별하지 않는다.
- 포인트색 한 가지: 자주 `#DB2777`.

## 9. 디버깅

- [ ] 짚기 전에는 `오른쪽`이 흐리다.
- [ ] 짚기는 판마다 한 번이다. 두 번째로 다른 칸을 눌러도 옮겨 가지 않는다.
- [ ] 시험을 한 번이라도 한 뒤에는 짚지 못한다.
- [ ] `같거나 크면` 판에서 갈린 자리가 n이다.
- [ ] `보다 크면` 판에서 갈린 자리가 n+1이다.
- [ ] 경계 한쪽만 시험해서는 드러나지 않는다.
- [ ] 양쪽을 다 시험하면 드러난다.
- [ ] `다시 시작`은 값만 0으로 만들고 짚은 칸과 시험한 칸은 남긴다.
- [ ] `다음 판`이 규칙과 기준값을 새로 낸다.
- [ ] 화면 어디에도 맞힌 판 수·점수·등수가 없다.

## 10. 앞판이 왜 재미없었나 (2026. 9. 17.)

앞판은 이랬다. 기준값 막대를 밀면 0~15 띠의 하트·가위표가 한꺼번에 바뀐다.
`왼쪽`으로 값을 올리고 `오른쪽`으로 LED를 바꾼다. 끝.

공통기준을 하나도 어기지 않았고 감사 3종을 통과했는데 **게임이 아니었다.**

- 해내야 할 것이 없었다. 띠가 답을 처음부터 다 보여 주고 있었다.
- 못 할 여지가 없었다. 아무렇게나 눌러도 아무 일도 안 난다.
- 두 번 할 까닭이 없었다. 한 번 밀어 보면 끝이다.

그때 한 "재미 검토"는 **갈리는 순간 LED가 0.17초 커졌다 돌아오게** 한 것이었다.
재미없는 것 위에 칠을 한 것이지 재미를 만든 것이 아니다.

고친 자리는 하나다. **답을 먼저 보여 주던 띠를, 답을 가리고 짚게 하는 띠로 바꿨다.**
같은 띠, 같은 규칙, 같은 버튼인데 짚기를 앞에 두자 게임이 됐다.

### 앞선 '안 만듦' 판정 (2026. 9. 11.)

> 만들지 않는다. 기준값 양쪽 시험은 활동3·4에서 실물 버튼으로 한다.

활동3의 아홉 번·열 번 시험에 대해서는 그대로 살아 있다.
