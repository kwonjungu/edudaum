## 4. 조작과 값

**학습 사진 구성(31차시 활동1 구성표 그대로).**

| 줄 | 장수 |
|---|---|
| 오른손 · 밝은 곳 | 24 |
| 왼손 · 밝은 곳 | 4 |
| 긴소매 · 밝은 곳 | 2 |
| 오른손 · 어두운 곳 | 0 |
| 모두 | **30** |

**쓸 사람 다섯 (셋을 고른다).**

| 사람 | 닮은 사진이 있는 줄 |
|---|---|
| 오른손 · 교실 | 오른손 · 밝은 곳 |
| 왼손 · 교실 | 왼손 · 밝은 곳 |
| 긴소매 · 교실 | 긴소매 · 밝은 곳 |
| 오른손 · 복도 | 오른손 · 어두운 곳 |
| 반창고 손 · 교실 | **없음** |

**바꾸는 값은 하나다.** 사진 열 장을 넣을 곳은 한 곳만 켜진다. 다른 곳을 누르면
앞의 것이 꺼지고 새 곳이 켜진다. 두 곳을 한꺼번에 채울 수 없다.

| 더 넣기 | 바뀌는 줄 |
|---|---|
| 왼손 열 장 | 왼손 · 밝은 곳 4 → 14 |
| 긴소매 열 장 | 긴소매 · 밝은 곳 2 → 12 |
| 어두운 곳 열 장 | 오른손 · 어두운 곳 0 → 10 |

**판정 규칙(하드코딩 아님).** 그 사람과 닮은 사진이 몇 장인지로만 갈린다.

```
여덟 장 이상  → 잘 알아봐요
한 장에서 일곱 장 → 자주 놓쳐요
없음          → 거의 못 알아봐요
```

읽히는 것 셋.

1. **오른손·교실 사람은 처음부터 24장이라 늘 잘 알아본다.** 전체가 나쁜 것이 아니라
   한쪽에만 불편이 쌓인다.
2. **한 곳에만 넣을 수 있으므로, 고른 셋 가운데 누군가는 반드시 그대로 남는다.**
   조건을 하나만 바꾸는 방법의 한계가 결과로 드러난다.
3. **반창고 손 사람은 세 버튼 어느 것으로도 0장에서 움직이지 않는다.** 자료를 더 모아도
   나아지지 않을 수 있고, 애초에 자료에 없던 사용자가 있다(32차시 정리 유의사항).
   화면에는 이 말을 적지 않았다. `아직 빠진 사람은 누구인가요?` 한 줄만 띄운다.

## 7. 만드는 방법

- 외부 라이브러리 **없음**. CDN 주소 **없음**. 바닐라 JS, 인라인 CSS·SVG.
- 손 네 가지(오른손·왼손·긴소매·반창고)와 해·달은 `<symbol>`로 그리고 `<use>`로
  꺼내 쓴다. 이모지를 쓰지 않는다.
- 어두운 곳은 아이콘 바탕색(연회색)과 글자 라벨 `어두운 곳`으로 함께 알린다.
  색으로만 구별하지 않는다. 막대는 길이·숫자·글자 라벨 셋으로 읽힌다.
- 상태는 객체 하나(`st`)에 모은다. `{picked: [], add: null}`. 막대 장수는 상태에 없다.
  `countOf(k)`가 밑값에 `add`를 더해 그때그때 센다. 화면에 보이는 숫자가 한 군데에서만
  나온다.
- 사람 버튼과 더 넣기 버튼은 한 번만 짓고(`buildPeople` `buildAdds`) 뒤로는
  `aria-pressed`만 갈아 끼운다. 막대와 점검표만 다시 그린다.
- 두 번 눌림 막기: 고르기·넣기는 모두 토글이다. 같은 버튼을 두 번 누르면 켜졌다 꺼지고,
  같은 일이 두 번 일어나지 않는다.

```
countOf(k) → 그 줄의 밑값 + (add가 그 줄이면 10)
verdict(n) → 8 이상 / 1 이상 / 0 의 세 갈래
onPick()   → 이미 고른 사람이면 빼고, 아니면 셋까지만 넣는다
onAdd(k)   → add가 k면 null, 아니면 k. 두 곳이 동시에 켜지지 않는다
reset()    → picked 비우고 add 지운다. 판 1로 돌아간다
```
