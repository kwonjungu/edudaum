# B01 체험 활동 설계 — 물건 카드 두 칸 나누기

2026. 10. 11. 지도안(검토반영본)에 맞춰 새로 짰다. 앞의 「신호등 명령 바꾸기」 설계는 맨 끝 절에 줄여 남긴다.
화면과 문서에서 사람에게 보이는 이름은 '게임'이 아니라 **체험 활동**이다(사용자 지시, 2026. 10. 11.).
짜임은 `_게임설계.md`의 `판이 나온다 → 짚는다 → 확인한다`를 그대로 따른다.

## 0. 만들까 말까 · 지도안 어디에 붙나

**만든다.**

지도안 1차시 전개 활동1 「하드웨어·소프트웨어 나누기 놀이 (12분)」의 이 줄 자리다.

> - 물건 카드를 하드웨어 칸·소프트웨어로 분류하는 게임하기
> (사진에 하이퍼링크 연결)
> ★ 물건 카드 분류 웹앱 게임

교사가 링크를 걸어 둘 웹을 찾던 자리라서, 이 체험 활동이 그 링크가 된다.
**앞**: `교사 마이크로비트를 돌려 보며 LED·버튼·칩 가리켜 보기` / `만질 수 있는 몸체와 부품은 하드웨어임을 적기` /
`하트가 3으로 바뀐 까닭이 명령(소프트웨어)임을 적기`.
**뒤**: `한 물건 속 두 가지 찾기: 계산기 몸체·버튼 / 곱셈 명령`.
교실에서 4~5분. 활동2 학교 SW 탐험(실물 사진·현장 메모)은 그대로 한다.

지도안 유의점이 이 활동의 과녁이다.

> △ 하드웨어와 소프트웨어는 한 물건 안에 함께 있음을 알려 주고, 물건 전체를 한쪽으로만 나누지 않게 한다.

그래서 **물건 카드 한 장을 통째로 한 칸에 넣지 않는다.** 카드 한 장을 조각 네 개(부품과 `언제 → 무엇을 한다` 명령)로
풀어 두 칸에 나누게 하고, 확인하면 대개 **두 칸이 다 찬다**는 것을 눈으로 본다.
지도안 활동2의 도전 `SW 없는 물건 하나와 짝지어 찍기`에 맞추어, 소프트웨어가 없는 물건 카드(손으로 돌리는 연필깎이)가
가끔 섞인다. 그래서 `무조건 둘 다`로 외워 버릴 수 없다.

- 웹이 아니면 못 하는가: 종이 카드는 나눈 뒤 바로 견줄 기준이 없다. 화면은 넣은 칸과 실제 칸을 곧바로 맞대어 준다.
- 값을 바꾸면 결과가 바뀌는가: 조각을 어느 칸에 넣느냐에 따라 옮겨 가는 조각 수가 달라진다.

## 1. 게임 다섯 칸 (`_게임설계.md` 1절)

| 칸 | 이 활동 |
|---|---|
| 목표 | 물건 카드 속 조각 네 개를 하드웨어 칸·소프트웨어 칸에 나눈다 |
| 실패 | 다른 칸에 넣은 조각은 확인할 때 건너간다(`한 조각이 다른 칸으로 옮겨 갔어요`) |
| 예상 | 나누기 **전에** `이 물건엔 무엇이 들어 있을까` — 하드웨어만 / 소프트웨어만 / 둘 다 를 먼저 고른다 |
| 제약 | 예상을 고르기 전엔 조각을 못 넣는다. 네 조각을 다 넣기 전엔 확인이 잠긴다. 확인한 뒤엔 바꾸지 못한다 |
| 되풀이 | `다음 물건`마다 물건 카드와 조각 네 개를 새로 뽑는다(직전 카드는 안 나옴) |

다섯 칸 모두 찬다.

## 2. 한 문장

조각을 두 칸에 나누고 확인하면, 한 물건 안에 하드웨어 칸과 소프트웨어 칸이 함께 찬다.

## 3. 화면 (1화면, 세로로 쌓임)

| 구역 | 보이는 것 | 학생이 하는 것 |
|---|---|---|
| 물건 카드 | 물건 이름(예: 보건실 체온계), `예상` 단추 셋 | 예상 하나를 고른다(확인 전엔 바꿀 수 있음) |
| 조각 | 아직 안 넣은 조각들. 맨 앞 조각이 `들고 있는` 표시 | 조각을 눌러 집는다(넣은 조각도 다시 집을 수 있음) |
| 두 칸 | `하드웨어 칸` · `소프트웨어 칸` 단추와 그 아래 넣은 조각 | 칸 단추를 눌러 들고 있는 조각을 넣는다 |
| 아래 | `확인하기` `다시 하기` `다음 물건`, 결과 두 줄 | 확인한다 |

넣으면 다음 남은 조각을 저절로 집는다. 그래서 칸 단추만 네 번 눌러도 나누기가 끝난다(첫 조작 10초 안).

**확인한 뒤**
- 다른 칸에 넣은 조각은 제 칸으로 건너가고 `옮김` 딱지가 붙는다(색만으로 구별하지 않음).
- 모든 조각 아래에 까닭 딱지: 하드웨어 `만질 수 있는 몸체·부품`, 소프트웨어 `사람이 미리 정해 준 명령`.
  지도안의 `만질 수 있는 몸체와 부품은 하드웨어` / `소프트웨어는 사람이 미리 정해 준 명령의 묶음` 말 그대로다.
- 결과 첫 줄(예상): 아래 6절.
- 결과 둘째 줄(조각): `넣은 칸 그대로였어요` / `두 조각이 다른 칸으로 옮겨 갔어요`.
- 예상과 조각을 모두 한 칸에만 몰았는데 두 칸이 다 찼으면 `한 칸에 다 넣었는데 두 칸으로 갈렸어요`.

## 4. 판과 값

물건 카드 여섯 장(지도안 탐험 구역: 교실·복도·현관·보건실·도서관과 도입의 마이크로비트·계산기에서 고름).
조각은 판마다 카드의 조각 묶음에서 **네 개를 뽑는다.** 하드웨어 수는 1~3개에서 뽑고(소프트웨어가 있는 카드),
남는 자리는 소프트웨어 조각이다. 순서는 섞는다. 직전과 같은 카드는 다시 뽑는다. 연필깎이는 6장에 1장꼴.

| 카드 | 하드웨어 조각 | 소프트웨어 조각(`언제 → 무엇을 한다`) |
|---|---|---|
| 계산기 | 숫자 버튼 / 숫자가 뜨는 화면 / 플라스틱 몸체 / 안에 든 건전지 | × 버튼을 누르면 → 두 수를 곱한다 / = 버튼을 누르면 → 답을 화면에 띄운다 / 한참 안 쓰면 → 화면을 끈다 |
| 보행자 신호등 | 빨강·초록 전구 / 건너기 누름 버튼 / 쇠기둥 | 누름 버튼을 누르면 → 초록불을 켠다 / 초록불 20초가 지나면 → 빨간불로 바꾼다 / 끝나기 5초 전 → 초록불을 깜빡인다 |
| 현관 자동문 | 유리문 / 사람을 알아채는 센서 / 문을 미는 모터 | 사람이 다가오면 → 문을 연다 / 아무도 없으면 → 5초 뒤 닫는다 / 문 사이에 무엇이 있으면 → 닫지 않는다 |
| 보건실 체온계 | 끝에 달린 온도 센서 / 숫자 화면 / 재기 단추 | 단추를 누르면 → 온도를 잰다 / 37.5도가 넘으면 → 삐 소리를 낸다 |
| 마이크로비트 | LED 25개 / A 버튼 / 작은 칩 | A 버튼을 누르면 → 하트를 보여 준다 / B 버튼을 누르면 → 숫자 3을 보여 준다 |
| 손으로 돌리는 연필깎이 | 칼날 / 돌리는 손잡이 / 톱니바퀴 / 가루 통 | (없음) |

일부러 넣은 헷갈림: `사람을 알아채는 센서`, `온도 센서`, `숫자가 뜨는 화면`처럼 **하는 일이 적힌 부품**.
하는 일이 적혀 있어도 만질 수 있으면 하드웨어다. 의견이 갈릴 만한 조각(예: `화면에 뜬 숫자`)은 넣지 않는다
(지도안 `의견이 나뉘는 물건은 답을 알려 주지 말고` — 화면이 판정을 내리는 자리를 만들지 않음).

| 자리 | 문구 |
|---|---|
| 제목(h1) | 물건 카드 두 칸 나누기 (11자) |
| 부제(lead) | 한 물건 속 조각을 하드웨어·소프트웨어 칸에 나눠요 (26자) |
| 예상 물음 | 이 물건엔 무엇이 들어 있을까 |

| 단추 | 확인하기 / 다시 하기 / 다음 물건 |

## 6. 결과 문구 (예상 줄)

| 예상 \ 실제 | 두 칸 다 참 | 하드웨어 칸만 참 |
|---|---|---|
| 둘 다 | 예상대로 두 칸이 다 찼어요 | 소프트웨어 칸은 비었어요 |
| 하드웨어만 | 소프트웨어 칸에도 조각이 들어갔어요 | 예상대로 하드웨어 칸만 찼어요 |
| 소프트웨어만 | 하드웨어 칸에도 조각이 들어갔어요 | 소프트웨어 칸은 비고 하드웨어 칸만 찼어요 |

좋고 나쁨을 매기지 않고 **칸이 어떻게 찼는지만** 말한다.

## 7. 만드는 방법

외부 라이브러리 없음. 단일 HTML. 저장·전송 없음. 센서 없음(지도안 1차시는 눈과 손으로 가리키기만 한다).

```
판 = { card, pieces[4]: {text, kind:'hw'|'sw', put:null|'hw'|'sw'} }, guess=null, held=0, done=false
newRound(): 카드 뽑기(직전 제외), 조각 뽑기·섞기, guess=null, held=0, done=false
guessPick(g): done이면 무시. guess=g
holdPiece(i): done이거나 guess 없으면 무시. held=i
drop(col): done이거나 guess 없거나 held 없으면 무시.
  pieces[held].put=col; held = 아직 안 넣은 첫 조각 또는 null
확인(): guess 있고 네 조각 다 넣었을 때만. done=true
  moved = put != kind 인 조각 수. 조각을 kind 칸으로 옮기고 '옮김' 딱지
  예상 줄 = 6절 표, 조각 줄 = moved
다시 하기: 같은 카드·같은 조각, 넣은 칸·예상만 비운다
```

## 8. 난이도 점검

첫 조작 5초(예상 단추), 1화면, 누를 것 12개(예상 3·조각 4·칸 2·아래 3) — 공통기준 3절 `조작 요소 5개 이하`를 넘는다.
까닭: 조각 넷과 칸 둘이 하나의 '나누기' 조작이다. 줄이면 물건을 통째로 한 칸에 넣는 꼴이 되어 지도안 유의점을 어긴다.
한 번에 바꾸는 값은 조각 하나의 칸. 4~5분.

## 9. 디버깅

- [ ] 예상 전에 칸 단추를 눌러도 아무 일 없다(흐림 + 한 줄).
- [ ] 네 조각을 다 넣기 전엔 확인이 잠긴다.
- [ ] 넣은 조각을 다시 눌러 다른 칸으로 옮길 수 있다(확인 전).
- [ ] 확인 뒤 조각·칸·예상이 잠기고 옮긴 조각에 `옮김`이 붙는다.
- [ ] 다음 물건에서 직전 카드가 나오지 않는다.
- [ ] 연필깎이 카드에서 소프트웨어 칸이 비고 문구가 맞게 나온다.
- [ ] 폭 390에서 두 칸이 나란히 들어가고 가로 스크롤이 없다.

## 10. 교사 검토 (2026-10-11)

- 까닭 딱지를 지도안 말로 맞춤: `만질 수 있는 몸체·부품` / `사람이 미리 정해 준 명령`(도입에서 기록지에 적는 문장).
- 계산기 조각 `× 누르면`을 `× 버튼을 누르면`으로. 기호만 있으면 5학년이 무엇을 누르는지 헷갈린다.
- 상시 줄을 지도안 다음 활동(`한 물건 속 두 가지 찾기`, 기록지)에 잇도록 바꿈.
- 확인: 화면이 판정을 대신하는 '의견이 나뉘는 물건'은 카드에 없다. 실물 탐험(활동2)을 대신하지 않는다. 센서·카메라 없음.

## 11. 재미 검토 (2026-10-11)

- 흐름 확인: 판(물건 카드·조각 넷) → 짚기(예상 + 칸 넣기, 확인 전엔 몇 번이든 바꿈) → 확인(잠김). 예상 전 칸 잠금, 네 조각 전 확인 잠금.
- 확인한 순간 옮겨 간 조각만 한 번 튄다(`prefers-reduced-motion`에서 꺼짐).
- 확인 뒤 주 단추가 `확인하기`에서 `다음 물건`으로 넘어가 다음 판으로 바로 손이 간다.
- 폭 390에서 결과 칸이 접힘 아래로 내려가므로, 확인하면 결과 칸까지 스크롤한다.
