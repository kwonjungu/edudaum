# B22 체험 설계 — 날씨 카드를 넣으면

## 0. 만들까 말까

**만든다.**

- 비·미세먼지·기온이 섞인 날씨 카드를 판마다 새로 뽑아 **확인 순서에 따라 결론이 갈리는 것**을 여러 번 겪게 한다. 교실의 날씨 카드는 다섯 장뿐이고, 경계값(28·33도)과 순서를 바꾼 판을 빠르게 되풀이하는 것은 웹이 낫다.
- 짚고 확인하는 한 번이 10초 안에 끝난다. 브라우저만으로 되고 5분 안에 끝난다.

**되돌아본 점.** 활동2의 엔트리 도우미 만들기와 활동3의 시험 단추 넣기는 실물이 본론이다. 이 웹은 블록을 대신 놓아 주지 않고, 날씨 블록을 흉내 내지도 않는다. 규칙표를 **읽는 순서**만 다룬다.

## 1. 과정안 어디에 붙는가

- 블록 B22, 15~16차시. 두 자리에 쓴다.
  - **활동1. 판단 지식을 규칙표로 옮기기** 뒤: 날씨 카드 다섯 장을 규칙표로 먼저 판정해 적은 **다음**, 엔트리로 넘어가기 전에 3분.
  - **활동3. 날씨 카드로 시험하고 규칙 순서 바꿔 보기** 뒤: 기온 규칙을 맨 앞으로 옮겨 비 오는 30도 카드를 넣어 본 **다음**, 까닭을 쓰기 전에 3분.
- 활동2(엔트리 날씨 블록으로 도우미 만들기)·활동3의 시험 단추를 대신하지 않는다. 화면 한 줄 `엔트리 도우미에도 넣어 봐요`를 상시로 둔다.
- 교실에서 한 번에 3~5분.

## 2. 한 문장

판마다 나온 **날씨 카드**(기온·비·미세먼지)를 규칙표 순서대로 따라가 어느 결론이 나올지 짚고, 기온 규칙이 맨 앞으로 옮겨진 판에서는 **같은 카드의 결론이 달라지는 것**을 겪는다.

## 3. 게임 (2화면, 한 쪽에 세로로)

**해내야 할 것**: 판마다 나온 날씨 카드 한 장에 어느 결론이 나올지 짚어라.

| 화면 | 보이는 것 | 학생이 하는 것 | 제약 |
|---|---|---|---|
| ① 이번 날씨 카드·확인 순서 | 큰 기온 숫자, `비 옴/비 안 옴`·`미세먼지 ○○` 딱지, 규칙 네 줄 + `그 밖에` 한 줄 | 순서를 따라간다(조작 없음) | 셋에 한 판꼴로 기온 규칙이 맨 앞에 온다 |
| ② 결론 고르기 | 결론 네 갈래 | 하나를 짚고 확인하기를 누른다 | 짚기는 판마다 한 번, 확인 전엔 못 무른다 |

확인하기를 누르기 전에는 어느 줄이 걸렸는지 안 보인다.

## 4. 조작과 값

- 조절하는 값: 없음(카드는 판이 뽑는다). 학생이 하는 것은 **결론 하나를 짚는 것**뿐이다.
- 판마다: 기온 15~37도(정수, 30%는 경계값 28·33), 비 35%, 미세먼지 좋음 40%·보통 35%·나쁨 25%. 15%는 과정안의 **비 오는 30도 카드**(미세먼지 보통)를 그대로 낸다. 확인 순서는 기본 [비 → 미세먼지 → 33도 → 28도], 1/3 확률로 [33도 → 28도 → 비 → 미세먼지](활동3의 "기온 규칙을 맨 앞으로"). 직전 판과 같으면 다시 뽑는다.
- 규칙표는 과정안 활동1 예시 그대로다. **조건과 결론은 학생이 못 고친다.**

| 조건 | 결론 |
|---|---|
| 비가 오면 | 강당 수업 |
| 미세먼지 나쁨이면 | 실내 수업 |
| 33도 이상이면 | 실내 수업 |
| 28도 이상이면 | 그늘에서 짧게 |
| 그 밖에 | 운동장 수업 |

- 반영: 보이는 순서대로 위에서부터 확인해 처음 걸린 줄의 결론이 답이다. 기온이 앞에 온 판에서 비 오는 30도 카드는 `강당 수업`이 아니라 `그늘에서 짧게`가 된다.
- `다시 하기`는 확인 전 짚은 것만 지운다. `다음 판`은 카드·순서를 새로 뽑는다.

## 7. 만드는 방법

- 순수 JS. 외부 라이브러리 **없음**. 포인트색 한 가지(앰버). 줄은 ①~④ 번호와 `→ 결론` 글자로 가른다.

```
RULES = [비→강당, 미세먼지 나쁨→실내, 33이상→실내, 28이상→그늘에서 짧게]
BASE = [0,1,2,3] ; TEMP_FIRST = [2,3,0,1]
fire(order, card): for i in order: if RULES[i].f(card): return i ; return -1(운동장 수업)
```
