# B11 체험 설계 — 흔들면 세는 주머니

2026. 9. 17. 판정을 뒤집었다. 앞선 판정문은 9절에 남겨 둔다.

## 0. 만들까 말까

**만든다.** 단, 앞 판정이 막았던 자리(복도 실측·두 수의 차이)는 그대로 막아 둔다.

- **웹이 아니면 못 하는가.** 학생은 마이크로비트를 받기 전에 "흔들림을 센다"가 무슨 뜻인지
  모른 채 블록을 놓는다. 태블릿 가속도계는 그 감각을 **몸으로 먼저** 준다. 종이로는 안 된다.
- **값을 바꾸면 결과가 바뀌는가.** 목표 횟수를 고르면 표시가 갈리는 지점이 옮겨 간다(활동5).
  흔들면 숫자가 오른다(활동2). 되돌리기가 값을 0으로 만든다(활동4).

**여전히 만들지 않는 것.** 복도 실측, 직접 센 걸음과 기기 수의 **차이**, 차이의 까닭.
이 셋은 학급마다 다르게 나와야 하므로 화면이 먼저 보여 주지 않는다. 화면은 숫자 하나만 센다.

---

## 1. 과정안 어디에 붙는가

- 블록 B11, 21~24차시. **21차시 활동1 뒤, 활동2(전송) 앞**에 3~5분.
- 활동1에서 "흔들림을 셀 때 할 일"과 "목표 횟수"를 종이에 적은 **다음**, 케이블을 나누기 전에
  손으로 한 번 겪는다. 활동2의 전송을 대신하지 않는다.
- 23차시 활동10의 "걷지 않고 기기만 흔들었을 때" 를 미리 한 번 만나 두는 자리이기도 하다.

---

## 2. 한 문장

태블릿을 **흔들면** 주머니 속 수가 1씩 오르고, 고른 **목표 횟수**를 넘는 순간 표시가 갈린다.

---

## 3. 화면 (1화면, 스크롤 없이)

| 구역 | 보이는 것 | 학생이 하는 것 |
|---|---|---|
| 위 | 제목·부제, 안전 한 줄 | 읽지 않아도 된다 |
| 가운데 | **큰 수**(주머니 값)와 5×5 점 격자 | 태블릿을 흔든다 |
| 아래 | 목표 세 개(10·20·30), `흔들기`, `다시 하기` | 목표를 고른다 / 못 흔들면 누른다 |

- 5×5 점 격자는 마이크로비트 화면을 그대로 옮긴 것이다. 목표를 고르기 전에는 **값만큼 점이 찬다**.
- 목표를 고르면 두 가지 표시로 갈린다. **목표 아래**는 가운데 한 점, **목표 이상**은 격자 전체가 찬다.
- 목표를 고르지 않은 상태로 시작한다(5-4: 학생이 채울 칸을 미리 채우지 않는다).

---

## 4. 조작과 값

- 조절하는 값: **목표 횟수** 하나. `10 / 20 / 30` 가운데 하나. 처음엔 고르지 않은 상태.
- 주된 조작: **흔들기**(센서). 센서가 없으면 `흔들기` 버튼을 누르기.
- 보조 조작: `다시 하기`(값을 0으로 — 과정안 B 버튼과 같은 일).
- 값의 상한 99. 99에서 멈춘다(마이크로비트 화면이 두 자리인 것과 맞춘다).

**재미 검토(2026. 9. 17.)에서 더한 것.** 목표를 고르면 격자가 `가운데 한 점`에 멈춰 있어
아무리 흔들어도 화면이 달라지지 않았다. 마이크로비트 동작으로는 맞지만 흔드는 맛이 죽는다.
격자 규칙은 그대로 두고 **숫자 쪽에만** 셋을 더했다.
- 큰 수 아래에 `/ 20` 꼴로 고른 목표를 함께 적는다(글자 4자). 숫자가 진행감을 맡는다.
- 값이 오를 때 숫자가 0.13초 커졌다 돌아온다.
- **목표를 처음 넘는 그 한 번만** 격자 바탕이 0.5초 번쩍인다. 되풀이해서 번쩍이지 않는다.
- 셋 다 `prefers-reduced-motion`에서 꺼진다.

**흔들림 판정**
- `devicemotion`의 `accelerationIncludingGravity`에서 직전 표본과의 차이 크기를 구한다.
  `d = |x-px| + |y-py| + |z-pz|`
- `d > 16`이면 한 번으로 센다. 센 뒤 **250ms 동안은 다시 세지 않는다**(되풀이 방지).
- 표본은 오는 대로 받되 처리는 50ms마다 한 번만 한다.

**열어 두는 딴짓.** 걷지 않고 손목만 털어도 값이 오른다. **막지 않는다.** 이것이 23차시 활동10의 알맹이다.

**쓰지 않는 말**: 변수, 센서, 가속도, 만보기, 인공지능. 값 이름은 `주머니` 하나로만 부른다.
정의문을 넣지 않는다.

## 6. 연습 모드

| 막히는 것 | 처리 |
|---|---|
| `DeviceMotionEvent`가 없음 | 바로 연습 모드. `흔들기` 버튼으로 1씩 올린다. |
| iOS 권한이 필요함 | `흔들기` 버튼을 그대로 두고, 누르면 권한을 물어본다. 거부하면 연습 모드로 남는다. |
| 권한 거부·기기 없음 | 연습 모드. 한 줄로 알린다. |
| 화면을 벗어남 | 듣기를 끊는다(`visibilitychange`, `pagehide`). 값은 남긴다. |

연습 모드에서도 목표에 따라 표시가 갈리는 것은 똑같다. `진짜와 같다`고 적지 않는다.

## 7. 만드는 방법

외부 라이브러리 없음. CDN 없음. 저장 없음.

```
값 count = 0, 목표 goal = null, lastShake = 0, prev = null
onDeviceMotion(e):
  a = e.accelerationIncludingGravity;  if (!a) return
  if (prev):
    d = |a.x-prev.x| + |a.y-prev.y| + |a.z-prev.z|
    if (d > 16 && now - lastShake > 250): bump()
  prev = {x:a.x, y:a.y, z:a.z}

bump():
  lastShake = now
  count = min(count + 1, 99)
  숫자만 다시 그린다        // 화면 전체를 다시 그리지 않는다 (8-3)
  격자를 다시 그린다

격자():
  if (goal === null)   값만큼 점 25칸 가운데 앞에서부터 채운다 (99는 25로 자른다)
  else if (count < goal) 가운데 한 칸만 채운다
  else                  25칸을 모두 채운다

다시하기(): count = 0; prev = null; 다시 그린다   // goal은 그대로 둔다
```

- 격자 점 25개는 인라인 SVG `<rect>` 25개. 채움은 `fill` 하나만 바꾼다.
- 목표 버튼은 `aria-pressed`로 고른 것을 표시한다. 색으로만 구별하지 않는다(5-5).
- `흔들기` 버튼은 센서가 붙어도 **없애지 않는다.** 흔들 수 없는 자리에 앉은 학생이 쓴다.
- 포인트색 한 가지: 주황 `#FF7A00`.

## 9. 디버깅

공통기준 8-2에 더해 이 차시만의 항목.

- [ ] 한 번 크게 흔들었을 때 값이 **1만** 오른다(250ms 잠금이 듣는다).
- [ ] 세게 30번 흔들어도 숫자가 건너뛰지 않는다.
- [ ] 목표를 고르지 않은 채 흔들어도 격자가 값만큼 찬다.
- [ ] 목표를 고른 뒤 값이 목표를 넘는 순간 격자가 한 점 → 전체로 바뀐다.
- [ ] 목표를 도중에 바꿔도 값은 그대로다.
- [ ] `다시 하기`가 값만 0으로 만들고 목표는 남긴다.
- [ ] 다른 앱으로 갔다 오면 값이 혼자 오르지 않는다.
- [ ] 99에서 멈춘다.
- [ ] 센서가 없는 노트북에서 `흔들기` 버튼만으로 끝까지 된다.

### 앞선 판정문 (2026. 9. 11.)

> 만들지 않는다. 21~24차시의 본론은 복도에서 직접 걸으며 센 수와 기기 화면의 수를 짝지어 적고,
> 한 가지만 고쳐 다시 재는 일이다. 웹이 걸음을 흉내 내면 실측이 사라진다.

이 판정은 **활동7~10(복도 실측)에 대해서는 그대로 살아 있다.** 뒤집은 것은 활동1~2 사이의
3분짜리 자리뿐이다. 이 화면은 걸음을 세지 않는다. 흔들림만 센다.
