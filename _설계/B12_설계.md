# B12 체험 설계 — 처음 보는 안내기

## 0. 만들까 말까

**만든다.**

아무도 알려 주지 않는 상태로 낯선 안내기를 처음 쥐어 보는 일은 교실에서 재현하기 어렵다.
모둠 기기는 한 대이고 자기 작품은 자기가 만들어 이미 아는 탓에, 짝에게 건네도 "처음 쓰는
사람"이 되지 못한다(2절 1). 기기가 보여 줄 것을 하나씩 켜면 화면이 즉시 달라지므로 바꿀
값과 그 결과가 있다(2절 2). 3분이면 끝나고 브라우저만으로 돈다(2절 3·4).

실물과 겹치지 않는지도 따졌다. 활동5의 연습용 코드는 **판정과 근거를 기록지에 쓰는 법**을
익히는 자료다. 이 웹은 판정하지도 기록하지도 않고, 세 항목이 가리키는 차이를 몸으로 겪게만
한다(2절 끝 단서). 그래서 활동5 **앞**에 붙는다.

## 1. 과정안 어디에 붙는가

- 블록 B12, **27차시 활동5 앞 3분**. 활동5는 살펴볼 항목 세 가지를 읽고 연습용 코드에
  적용하는 일이므로, 그 항목이 무엇을 가리키는지 먼저 겪고 들어간다.
- 실물(연습용 코드 살펴보기)의 **앞**에 붙는 예상 활동이다.
- 화면에 판정 칸을 두지 않는다. 판정과 근거는 코드 살펴보기 기록지에 쓴다.

## 2. 한 문장

기기가 보여 줄 것을 하나씩 켜면, 같은 횟수를 흔들어도 화면이 알려 주는 것이 달라진다.

## 3. 화면 (1화면) — 2026. 9. 17. 게임으로 다시 짬

한 화면이다. 위에서 아래로 두 칸이고 스크롤 없이 들어온다. **값을 바꾸면 결과가 보이던**
첫판을, **물음이 나온다 → 두 개까지 켠다 → 확인한다**로 뒤집었다(`_게임설계.md` 2절).

| 칸 | 보이는 것 | 학생이 하는 것 |
|---|---|---|
| 이번 물음 | 물음 한 줄, 기기 화면(확인 전엔 비어 있음), 상태 한 줄 | 확인하고 결과를 본다 |
| 기기가 보여 줄 것 | 토글 버튼 다섯 개, `확인하기` `다시 하기` `다음 판` | 두 개까지 켜고 확인한다 |

넘어가는 조건을 두지 않는다. 다음 화면이 없다.

## 4. 조작과 값 — 게임으로 다시 짬

- 기기가 보여 줄 수 있는 다섯 가지: `지금 수` `목표` `남은 수` `목표를 넘었는지` `지난 시간`.
  처음엔 모두 꺼져 있다. **켤 수 있는 것은 두 개까지다.** 이 제약이 게임을 만든다
  (`_게임설계.md` 12절 — 제약 칸).
- 판마다 다섯 물음 가운데 하나가 나온다(예: `지금 몇 번 흔들었나요`, `목표까지 몇 번 남았나요`,
  `목표를 넘겼나요`, `목표가 몇 번인가요`, `흔든 지 얼마나 됐나요`). 물음마다 답이 되는
  조합이 여러 벌 있다 — `남은 수` 하나로도 되고, `지금 수`+`목표`로도 된다. `지난 시간`이
  답이 되는 물음은 하나뿐이라, 아무 정보나 켠다고 다 되는 게 아님을 겪는다(**목표** 칸).
- 판마다 `지금 수`(0~목표+4, 목표를 넘기기도 한다)·`목표`(6~14)·`남은 수`(=목표−지금 수,
  음수도 그대로 보인다)·`넘었는지`(예/아니요)·`지난 시간`(3~90초 전)을 그 자리에서 새로 뽑는다.
  값은 화면에 미리 적어 두지 않고 판을 뽑을 때 셈한다.
- 두 개를 고르고 `확인하기`를 누르면 그 둘만 기기 화면에 켜지고, 고른 조합이 이번 물음의
  정답 조합을 포함하면 `이걸로 알 수 있어요`, 아니면 `이걸로는 알 수 없어요`(**실패** 칸 —
  못 골라서 답할 수 없을 수 있다).
- **짚기는 판마다 한 번이다.** 확인하기 전에는 토글을 자유로이 켜고 끄지만(**예상** 칸 —
  확인 전에 이 조합으로 될지 스스로 걸어 보는 자리), 확인한 뒤에는 못 바꾼다. 두 개가 이미
  켜져 있으면 나머지 세 토글은 흐려지고 눌러도 반응하지 않는다.
- 되돌리기: 확인 전에는 `다시 하기`가 고른 것만 지운다. 확인한 뒤에는 `다시 하기`가
  `다음 판`과 같은 일을 한다(무를 수 없어서). `다음 판`은 물음과 값을 모두 새로 뽑되,
  **직전 판과 같은 물음이면 다시 뽑는다**(**되풀이** 칸).

## 5. 글자 (그대로 쓸 문구) — 게임으로 다시 짬

| 자리 | 문구 | 글자 수 |
|---|---|---|
| 제목 | 처음 보는 안내기 | 8 |
| 부제 | 두 개까지 켜서 물음에 답해요 | 14 |
| 소제목 | 이번 물음 / 기기가 보여 줄 것 | 5 / 9 |
| 상태(확인 전) | 켤 것을 골라요 / 확인하면 켜져요 | 7 / 8 |
| 상태(확인 후) | 이걸로 알 수 있어요 / 이걸로는 알 수 없어요 | 10 / 12 |
| 토글 버튼 | 지금 수 / 목표 / 남은 수 / 목표를 넘었는지 / 지난 시간 | 4/2/4/8/5 |
| 안내 | 두 개까지만 켜져요 | 9 |

`맞았어요`·`틀렸어요`·점수·등수를 쓰지 않는다. 답할 수 있는지 없는지만 말한다.

## 6. 연습 모드

막힐 것이 없다. 카메라·마이크·CDN·서버·저장을 하나도 쓰지 않아 인터넷을 끊고 파일을
두 번 눌러 열어도 그대로 돈다. 그래서 연습 모드를 따로 두지 않았다(7절과 다르게 한 점).

## 7. 만드는 방법

외부 라이브러리가 없다. CDN 주소가 없다. 단일 HTML 한 장에 style과 script를 담는다.
아이콘은 인라인 SVG로 그린다.

```
상태 = { 횟수:0, 켬:{시작:거짓, 숫자:거짓, 목표:거짓} }
목표 = 10, 최대 = 99

흔들기 누름 → 횟수 = 최소(횟수+1, 최대) → 그리기
켜는 버튼 누름 → 해당 켬 뒤집기 → 그리기
다시 하기 누름 → 횟수 0, 켬 셋 다 거짓 → 그리기

그리기:
  기기 밖 숫자 = 횟수
  기기 화면 =
    켬.목표 이고 횟수 >= 목표 → 체크 표시 (켬.숫자면 숫자도 함께)
    아니고 켬.숫자 이고 횟수 > 0 → 숫자
    아니고 켬.시작 이고 횟수 = 0 → 흔들기 그림 + 흔들어요
    그 밖 → 빈 화면
  버튼 세 개의 aria-pressed와 네모 안 체크를 켬 상태에 맞춘다
```

바뀐 곳(숫자·화면·버튼 세 개)만 고쳐 그린다. 화면을 통째로 다시 그리지 않는다.
