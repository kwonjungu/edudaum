# B12 체험 설계 — 수신기에 무엇이 뜰까

2026. 9. 27. 개정 과정안에 맞춰 **다시 짰다.** 옛 화면 「처음 보는 안내기」(흔들기 안내기에서 두 개까지 켜기)는
끝의 `개정 과정안 반영` 절에 까닭과 함께 남긴다.

## 0. 만들까 말까

**만든다.**

- **웹이 아니면 못 하는가.** 활동5는 교사가 만든 연습용 코드 **한 벌**에서 숨은 문제 세 곳을 찾는다.
  기기로 여러 벌을 겪으려면 판마다 두 대에 코드를 고쳐 다시 옮겨야 해서 한 시간에 한두 판밖에 못 한다.
  화면은 약속표·송신기·수신기 코드가 한 벌씩 짝지어진 판을 그 자리에서 끝없이 낸다.
- **값을 바꾸면 결과가 바뀌는가.** 그룹 번호 하나, `[만약]` 한 줄, 표시 하나가 바뀌면 수신 화면에 뜨는 것이 달라진다.
- 5분 안에 서너 판, 브라우저만으로 돈다. 외부 호출이 없다.

**여전히 만들지 않는 것.** 무선 전송·수신 자체(활동2~4·7의 실제 기기), 약속표 쓰기, 역할 교대, 외형 만들기,
코드 탐정 기록지 쓰기와 스티커 붙이기(활동5·6), 다른 모둠 도구 살펴보기. 화면은 무선을 흉내 내지 않는다 —
**코드를 읽고 무엇이 뜰지 먼저 거는 일**만 한다.

## 1. 과정안 어디에 붙는가

- 블록 B12, 25~28차시. **27차시 활동5 「코드 탐정 연습: 살펴볼 항목 익히기」 앞** 3~5분.
  (26차시 활동4 「이어 붙여 처음부터 끝까지 시험하기」를 마친 뒤)
- 활동5의 세 항목 가운데 **앞의 둘** — `그룹 번호가 같은가`, `약속 수마다 표시가 있는가` — 이 어긋나면
  수신 화면에 무엇이 일어나는지를 먼저 겪고 들어간다. 활동4의 `신호가 안 오면 그룹 번호·약속 수·전송 조건 순서로 살피기`와도 이어진다.
- 셋째 항목 `처음 쓰는 사람이 알아보는가`는 사람이 써 보아야 드러나므로 화면에 넣지 않는다.
- 판정·근거 쓰기는 코드 탐정 기록지에서 한다. 화면에 판정 칸이 없다.

## 2. 한 문장

약속표와 송신기·수신기 코드를 읽고 A를 누르면 수신 화면에 무엇이 뜰지 먼저 짚으면, 보내 보았을 때 드러난다.

## 3. 화면 (1화면)

| 칸 | 보이는 것 | 학생이 하는 것 |
|---|---|---|
| 통신 약속표와 코드 | 도구 이름·약속표 한 줄, 송신기 코드 카드, 수신기 코드 카드, 수신 화면(보내기 전엔 `?`) | 읽는다 |
| A를 누르면 무엇이 뜰까요 | 짚기 버튼 셋(약속표의 두 표시 + `안 뜸`), 상태 한 줄, `A 누르기` `다시 보기` `다음 판`, 되짚기 한 줄 | 하나를 짚고 보낸다 |

넘어가는 조건이 없다. 한 화면에서 끝내고 기기로 간다.

## 4. 조작과 값

- **판이 뽑는 것**(그 자리에서 뽑는다. 표로 적어 두지 않는다)
  - 도구: 과정안 25차시 도구 후보에서 셋 — `교실 소음 신호등`(1 → 빨간불, 0 → 초록불: 과정안 예시 약속표 그대로),
    `사용 중 알림판`(1 → 사용 중, 0 → 비었어요), `보건실 호출기`(1 → 와 주세요, 0 → 괜찮아요).
  - 보내는 수: 1 또는 0. 그룹 번호: 1~9.
  - 판의 갈래(여섯에 셋은 바른 판, 셋은 걸리는 판 — `_게임설계.md` 5절 "안 되는 판 셋에 하나쯤"보다 조금 많게):
    | 갈래 | 수신기 코드 | 수신 화면 |
    |---|---|---|
    | 바름 | 같은 그룹, 1·0 두 줄이 약속표대로 | 약속한 표시 |
    | 그룹 다름 | 그룹 번호만 다름 | 아무것도 없음 |
    | 줄 빠짐 | 보낸 수에 대한 `[만약]` 줄이 없음 | 아무것도 없음 |
    | 뒤바뀜 | 두 줄의 표시가 약속표와 뒤바뀜 | 다른 표시 |
  - 직전 판과 도구·수·갈래가 모두 같으면 다시 뽑는다.
- **짚기는 판마다 한 번, 무르지 못한다.** 짚기 전에는 `A 누르기`가 잠긴다.
- `A 누르기`: 수신 화면이 `받는 중`을 0.45초 보인 뒤 실제로 뜬 것을 보인다. 한 판에 한 번.
- `다시 보기`: 같은 판의 수신을 다시 보인다(짚은 것은 그대로). `다음 판`: 새로 뽑는다.
- 결과 문구는 **무엇이 떴는지만** 말한다. 좋고 나쁨을 매기지 않는다.

**화면이 먼저 답을 말하지 않는다.** 어느 줄이 걸렸는지 표시하지 않는다. 왜 안 떴는지는 학생이 코드 카드에서 찾는다 —
그것이 활동5에서 할 일이다.

## 7. 만드는 방법

외부 라이브러리 없음. 단일 HTML. 포인트색 `#FF5A5F`.

```
새판():
  도구 = 셋 가운데 하나; 수 = 1|0; 갈래 = [바름,바름,바름,그룹,빠짐,뒤바뀜] 가운데 하나
  (도구,수,갈래)가 직전과 같으면 다시 뽑기
  송신그룹 = 1~9; 수신그룹 = 갈래==그룹 ? 송신그룹과 다른 1~9 : 송신그룹
  줄들 = [1,0] 가운데 (갈래==빠짐이면 보낸 수 뺌), 표시 = 갈래==뒤바뀜 ? 약속(1-v) : 약속(v)
  실제 = 그룹이 같고 보낸 수의 줄이 있으면 그 줄의 표시, 아니면 없음

짚기(v): if 짚음 있음 or 보냄 → 무시; 짚음 = v
A누르기(): if 짚음 없음 or 보냄 → 무시; 보냄 = 참; 0.45초 뒤 실제를 수신 화면에
```

## 개정 과정안 반영 (2026-09-27)

기준: `_data/lessons.json` B12(25~28차시) 개정본 — 「송신기·수신기·안내 화면을 나누어 맡아 우리 학교 무선 도구를 만들고 서로의 코드 살펴보기」.

**판정: 재설계.** 붙는 자리(27차시 활동5 앞)는 그대로 두고, 게임의 대상을 바꿨다.

| 확인한 것 | 옛 화면 | 개정 과정안 | 결과 |
|---|---|---|---|
| 만드는 것 | 흔들기 **활동량 안내기**(지금 수·목표·남은 수) | 송신기·수신기·안내 화면으로 된 **무선 도구**(소음 신호등·사용 중 알림판·보건실 호출기 …) | 안내기 판을 버리고 약속표+송신기+수신기 판으로 |

**옛 화면을 버린 까닭.** `두 개까지 켜서 물음에 답하기`의 물음(목표까지 몇 번 남았나 등)이 개정본 어디에도 없고,
개정본 활동5의 항목과도 이어지지 않는다. 문구만 바꾸어서는 무선 도구의 코드 살펴보기에 붙일 수 없었다.

**허브·다른 문서.** 제목이 `처음 보는 안내기` → `수신기에 무엇이 뜰까`로, 부제가 바뀌었다. 허브(`index.html`)와
`_게임설계.md` 4절 표의 B12 줄은 이 작업 범위 밖이라 고치지 않았다 — 허브는 `_tools/make_hub.py`로 다시 만들면 따라온다.
