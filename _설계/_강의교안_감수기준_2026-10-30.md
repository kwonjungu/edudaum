# 블록 강의교안 — 만드는 방식과 감수 기준 (2026-10-30)

## 무엇을 만드나
- 블록(B01~B28)마다 교사가 수업 시간에 띄우는 **강의교안** 한 벌. 1280×720 HTML 슬라이드 + 인쇄용 PDF.
- 컨셉: **미션 해결단**. 책 속 캐릭터 일곱 명이 해결단원. 블록 = 미션. 흐름: 미션 받기 → 단서 찾기(활동지) → 직접 해 보기(체험) → 해결 보고(정리·연계 활동).
- 뼈대는 **교수학습 과정안**(`에듀다움_책만들기/work/plans/Bxx.txt`): 도입 → 전개 활동1·2… → 정리 차례, 차시·활동 꼬리표는 활동지와 같은 이름, 학습 문제는 과정안 문장 그대로.
- 캐릭터가 **말풍선**으로 진행: 직접 헤드리스로 캡처한 활동지·체험 화면의 한 곳을 가리키며 발문한다(과정안 발문을 옮김).
- 과정안에 유튜브 링크가 있으면 그 활동 슬라이드에 **▶ 영상 바로가기**(썸네일 + 링크, PDF에는 QR).
- 디자인: AIroom 소개 강의안의 틀(1280×720, 큰 제목+짧은 막대, 쪽 번호, 한 장에 한 메시지) + **따뜻한 풀 느낌**(아이보리 바탕, 풀빛·햇살 노랑·흙빛, Jua·Gowun Dodum, 둥근 카드, 옅은 풀 무늬).
- 놓는 곳: 누리집 `lecture/Bxx/`(블록 차시 쪽에서 "강의교안" 단추로 연결). **두 번 연이어 통과한 블록만** 하나씩 올린다.

## 감수: 세 팀이 각각 본다
감수 에이전트는 만든 사람과 다른 눈으로 본다. 파일을 고치지 않고 결과 json과 사진만 쓴다. 슬라이드 PDF를 쪽 그림으로 뽑아 **모든 장을 직접 본다.**
갈래마다 0·1·2점. 0점은 "이대로는 수업에 쓰면 안 되는 수준"에만 준다.

### A. 교육팀 (15년 차 초등 5·6학년 담임)

| A2 학생 눈높이 | 5·6학년이 읽고 바로 알아듣는 말, 한 장에 할 일 하나 | 풀이 없는 어려운 말, 한 장에 지시가 셋 이상 |
| A3 활동지·체험 연결 | 캡처가 그 활동의 실제 활동지 칸·체험 장면이고, 말풍선이 정확한 곳을 가리킨다 | 다른 활동의 화면, 엉뚱한 곳을 가리킴 |
| A5 집중·게임 | 활동 묶음마다 게임 장이 있고, 과정안 활동의 생각을 그대로 담으며, 학생이 손 들고 말할 거리가 있다 | 게임 장이 없거나 과정안과 상관없는 게임 |
| A4 원칙 | 판정·칭찬 말(맞았어요·틀렸어요·잘했어요·정답·오답·대단해요), 점수·등수 없음. 예측 → 확인 흐름 | 위 금지어나 점수·등수가 있음 |

### 판정
- **PASS = 세 팀 열네 갈래 모두 0점이 없다.** 하나라도 0점이면 FAIL.
- 1점은 PASS를 막지 않지만 고칠 곳을 적는다(`fix`).
- 결과: `_tools/_판정/lecture/Bxx_L{N}.json`
```json
{"block":"Bxx","round":N,"verdict":"PASS|FAIL","score":{"A1":2,"A2":2,"A3":2,"A4":2,"B1":2,"B2":2,"B3":2,"B4":2,"C1":2,"C2":2,"C3":2,"C4":2,"A5":2,"B5":2},"zero":["갈래: 어디 → 무엇이 → 고칠 방향"],"fix":["..."],"checked":"한 줄"}
```
- 마지막 답: `Bxx LN verdict` + 0점 갈래 고칠 곳만.

## 진행 순서
1. 캡처: 체험 28쪽(처음·예측 뒤·결과)과 연계 활동, 활동지 새 판 쪽 그림과 가리킬 칸 확대 컷, 책 캐릭터·표지. `lecture/_shots/`에 모으고 목록(json)으로 관리.
2. 링크 점검: 과정안 유튜브 링크 10개(B07·B11·B14·B25·B26)를 헤드리스로 열어 본다. 썸네일은 한 번 받아 로컬에 둔다.
3. 원고: 블록마다 과정안 → 슬라이드 원고(json). 생성기(`_tools/make_lecture.py`)가 HTML·PDF를 만든다.
4. **시범 블록 하나(B01)** 를 먼저 끝까지 만들어 감수 2회 연속 통과 → 누리집 반영 → 같은 틀로 나머지 블록.
5. 블록마다: 감수(한 번에 감수 하나만, 외부 에이전트) → 고치기(Claude) → 두 번 연이어 PASS → 누리집 반영(빌드·점검 후 커밋·푸시).
