작성일: 2026. 9. 27.

## 0. 한 문장

**과정안(hwpx)을 단 하나의 원본으로 두고, 그로부터 계획서·주제별 활동·차시별 과정안 쪽을 만들어 내며, 차시마다 연동 도구·교사 링크·체험 게임을 이어 붙인 교사용 누리집**을 만든다.

지금까지의 저장소는 "수업 중 5~10분 체험 게임 28개"만 있었다. 이번 확장으로 같은 주소가 에듀다움 교육과정의 **홈페이지**가 된다. 체험 게임은 그 안의 한 갈래로 남고, 규격(`_공통기준.md`)은 그대로 지킨다.

## 1. 왜 바꾸나 — 현황 진단

| 문제 | 내용 | 이번 설계의 답 |
|---|---|---|
| 게임과 과정안의 어긋남 | 게임 28개는 9월 17일 초안 과정안에 맞춰 만들었다. 이후 과정안이 크게 바뀌었다(B01 SW 지도·HW/SW 가르기, B11 무선 통신·게임, B12 무선 도구, B19 우리아이AI 팩트체크, B25 CreateAI 손 씻기 코치 등). | 28개 게임 전부를 개정 과정안과 대조해 붙는 자리·용어·예시를 다시 맞춘다(6절). |
| 과정안이 교사 손에 닿지 않음 | hwpx는 연구진 드라이브에만 있고, 휴대기기·교실 화면에서 열기 어렵다. | 과정안 전문을 웹 쪽으로 옮기고 PDF를 함께 둔다(4-5절). |
| 도구 주소가 흩어짐 | MakeCode·CreateAI·엔트리·KOSIS·우리아이AI 주소가 과정안 본문 곳곳에 글자로만 있다. | 차시마다 **연동 도구·링크** 칸을 두고, 교사가 자기 링크를 더 걸 수 있게 한다(5절). |
| 계획서·성취기준을 볼 곳이 없음 | 자체 성취기준과 연계 성취기준, 운영 구조가 여러 문서에 나뉘어 있다. | **계획서·성취기준** 쪽 한 장으로 모은다(4-2절). |
| 원본이 둘이 될 위험 | 웹에 과정안을 손으로 옮기면 hwpx와 웹이 따로 놀게 된다. | 웹은 hwpx에서 **기계로 뽑아** 만든다. 웹에서 과정안 문장을 고치지 않는다(3절). |

## 2. 정보 구조

### 2-1. 누리집 지도

```
/                       홈 — 네 갈래 입구, 64차시 지도, 운영 요약
├─ plan/                1) 계획서·성취기준
├─ topics/              2) 주제(영역)별 활동 내용 — 9개 영역
├─ lessons/             3) 차시별 교수학습 과정안 목록 — 학년별 표
│   └─ B01/ … B28/         차시 쪽 — 과정안 전문 + 연동 도구·링크 + 체험 게임 + PDF
├─ tools/               연동 도구 모음 — 도구별로 쓰는 차시
├─ play/                체험 게임 목록 (예전 허브)
├─ B01/ … B28/          체험 게임 (기존 주소 그대로 — 수업 중 이미 쓰는 링크를 깨지 않는다)
└─ assets/
    ├─ plan/BXX_n.jpg      과정안 그림 (hwpx에서 뽑아 줄인 것)
    └─ pdf/BXX.pdf         과정안 PDF (한글에서 내보낸 것)
```

### 2-2. 주소 규칙

- 과정안 쪽은 `lessons/BXX/`, 게임은 `BXX/`. **같은 블록 번호로 짝을 맞춘다.**
- 사람에게 보이는 이름은 블록 번호가 아니라 `6학년 9~10차시`다(`_tools/blocks.py` 한 곳에서 정한다).
- 기존 게임 주소(`/B19/`)는 바꾸지 않는다. 교사가 이미 수업 자료에 붙여 둔 링크가 있다.

### 2-3. 윗줄 메뉴

`에듀다움 | 홈 · 계획서·성취기준 · 주제별 활동 · 차시별 과정안 · 연동 도구 · 체험 게임`

- 모든 누리집 쪽 위에 고정한다(sticky). 좁은 화면에서는 줄을 바꿔 쌓는다.
- **체험 게임 쪽에는 이 메뉴를 넣지 않는다.** 게임 쪽은 공통기준(한 화면 250자, 첫 화면에 바로 조작)을 지켜야 하므로 윗줄에 `← 체험 목록`과 `과정안` 두 링크만 둔다(6-3절).

## 3. 데이터 흐름 — 원본은 하나

```
연구진 드라이브 hwpx 28편 (원본, 한글로 고친다)
        │  _tools/export_plans.py
        ▼
_data/lessons.json + assets/plan/*.jpg        ← 기계가 만든다. 손으로 고치지 않는다
_data/site.json · standards.json · tools.json · links.json   ← 사람이 고친다(누리집 고유 내용)
        │  _tools/make_site.py        BXX/index.html (게임: 사람이 만든다)
        ▼                                  │ 제목·부제·포인트색만 읽음
index.html · plan/ · topics/ · lessons/ · tools/ · play/
        │  _tools/public_copy.py → 공개용 사본(개발자 칸 = 연구회 이름, 작성자 정보 비움)
        │  _tools/hwpx2pdf.ps1 (한글 설치 PC) → public_copy.py --strip-pdf
        ▼
assets/pdf/BXX.pdf (공개용)
```

### 3-1. 데이터 파일

| 파일 | 누가 | 내용 |
|---|---|---|
| `_data/lessons.json` | 기계 | 차시별 개요(성취기준·핵심 역량·핵심 기능·가치 태도·학습 주제·학습 문제), 교수학습 활동 행(차시·단계·시간·본문·준비물/자료/유의점), 평가 계획(관점·목표·5수준·방법). 본문은 문단 순서 그대로이며 그림 자리를 `{img, caption}`으로 담는다. |
| `_data/site.json` | 사람 | 과정 이름, 이야기 틀, 9개 영역(학년·차시 범위·블록·성취기준·요약), 연계 성취기준 대응 |
| `_data/standards.json` | 사람(모의 CVR 확정본에서 옮김) | 자체 성취기준 14개 확정 문장, 블록별 코드 |
| `_data/tools.json` | 사람 | 외부 도구 목록(이름·주소·용도·계정·묶음·찾을 낱말·보조 링크) |
| `_data/links.json` | 사람 | 차시별 추가 링크(`extra`), 강제로 붙일 도구(`add`), 숨길 도구(`hide`), 드라이브 원본 id(`drive`) |

### 3-2. 과정안이 바뀌었을 때

1. 한글로 hwpx를 고친다(연구진 절차: specs → 하네스 H1~H10 → 이미지 → 한글 재저장).
2. `python _tools/export_plans.py "<hwpx 폴더>"`
3. `python _tools/public_copy.py "<hwpx 폴더>" "<공개용 폴더>"` → `powershell -File _tools/hwpx2pdf.ps1 -Src "<공개용 폴더>" -Out assets/pdf` → `python _tools/public_copy.py --strip-pdf assets/pdf`
4. `python _tools/make_site.py`
5. 바뀐 활동에 붙은 게임이 있으면 그 게임의 `_설계/BXX_설계.md` 1절을 다시 본다(6-4절).
6. `python _tools/run_all.py` — 게임 3종 + 누리집 점검까지 0건이어야 낸다.

**하지 않는 것:** 웹 쪽 HTML을 손으로 고쳐 과정안 문장을 바꾸는 일. 다음 생성 때 사라지고, 원본과 웹이 갈라진다.

## 4. 쪽별 설계

### 4-1. 홈 `/`

| 칸 | 내용 |
|---|---|
| 머리 | 연구회 이름, 「학교자율시간 SW·AI 교육과정」, 한 줄 소개 |
| 네 갈래 입구 | ① 계획서·성취기준 ② 주제별 활동 내용 ③ 차시별 교수학습 과정안 ④ 체험 게임 — 카드 네 장 |
| 64차시 지도 | 학년마다 32칸(16×2, 좁은 화면 8×4). 칸 = 차시 하나, 색 = 영역. 누르면 그 차시 과정안 쪽. 칸마다 `title`로 학습 주제를 띄운다. |
| 운영 요약 | 학년 32차시 전체 운영, 이야기 틀, "만들고 재고 고친다" 세 상자 |

### 4-2. 1) 계획서·성취기준 `plan/`

연구 계획서와 심층설계서에서 **공개해도 되는 요점**만 옮긴다.

1. 배경과 목표 — 34시간 이상 정보교육, 실과 17차시의 한계, 재구조화 근거([6실05-01]~[6실05-05], [06자율-1]~[06자율-7])
2. 운영 구조(고도화안) — 학년별 2학급 32차시 전체, 비교 학급 선택, 주 2차시 약 16주. 계획서의 1차 파일럿→2차 확대 구조에서 바뀐 점을 한 줄로 밝힌다.
3. 과정 구성 — 9개 영역 × 차시 범위 × 과정안 편수
4. **성취기준 표** — 학년 · 영역 · 자체 성취기준(코드+확정 문장) · 연계 성취기준 · 적용 차시(링크). 표 위에 "자체 코드는 국가 실과 코드가 아니다"를 밝힌다(모의 CVR 지적 반영).
5. 교과 연계 — 5·6학년 교과별
6. 평가와 검증 — 5수준 평가, 학년별 사전·사후 설문, 산출물 분석, CVR·하네스
7. 안전·개인정보 원칙 — 얼굴 대신 손·물건, 우리아이AI만 사용, 무선 그룹 번호, CCL, 설문 익명
8. 추진 일정 — 월별 표

**싣지 않는 것:** 연구진 성명·생년월일·연락처·참여율, 예산, IRB 번호(기입 전), 모의 CVR 원자료.

### 4-3. 2) 주제별 활동 내용 `topics/`

영역 아홉 개가 한 쪽에 차례로 놓인다. 쪽 머리에 영역 바로가기.

| 학년 | 영역 | 차시 | 과정안 |
|---|---|---|---|
| 5 | 생활 속 소프트웨어 | 1~4 | B01·B02 |
| 5 | 알고리즘 | 5~12 | B03~B06 |
| 5 | 프로그래밍 | 13~24 | B07~B11 |
| 5 | 협력과 공유 | 25~32 | B12~B14 |
| 6 | 인공지능과 우리 생활 | 1~6 | B15~B17 |
| 6 | 사람과 대화하는 인공지능 | 7~10 | B18·B19 |
| 6 | 규칙으로 판단하는 인공지능 | 11~16 | B20~B22 |
| 6 | 데이터로 학습하는 인공지능 | 17~26 | B23~B26 |
| 6 | 인공지능과 올바른 사용 | 27~32 | B27·B28 |

영역마다: 영역 요약 한 문단 → 성취기준 확정 문장 → 차시 카드(학년·차시 칩, 학습 주제, **활동 제목 목록**(과정안의 `◎ 활동N`을 그대로 뽑음), 연동 도구 칩, `과정안 보기`·`체험 게임` 단추).

영역 이름과 차시 범위는 연구 계획서의 영역 구분을 따르고, 요약 문장은 고도화된 과정안 내용으로 새로 썼다.

### 4-4. 3) 차시별 교수학습 과정안 목록 `lessons/`

학년별 표 한 장씩. 열: 차시 · 학습 주제(+영역) · 활동 제목 · 연동 도구 · 체험 게임.
교사가 "다음 주에 뭘 하지"를 한 화면에서 찾는 쪽이다.

### 4-5. 차시 쪽 `lessons/BXX/` — 핵심 쪽

위에서 아래로:

| 순서 | 칸 | 내용·근거 |
|---|---|---|
| 1 | 빵부스러기 | 차시별 과정안 › 영역 |
| 2 | 칩 | `6학년 9~10차시` · 영역 · 성취기준 코드 |
| 3 | 제목 | 학습 주제(`h1`) — 과정안 개요와 글자까지 같아야 한다(점검 S3) |
| 4 | 학습 문제 | 과정안 개요의 학습 문제 |
| 5 | 단추 줄 | `과정안 PDF`(공개용) · `체험 게임` · `연동 도구·링크` |
| 6 | 개요 표 | 성취기준(+연계), 핵심 역량, 핵심 기능, 가치 태도 |
| 7 | 활동 흐름 띠 | 행마다 `9차시 전개 활동1 · 활동2` 칩. 누르면 그 행으로 뛴다 |
| 8 | 교수학습 활동 | 행 카드: 머리(차시·단계·시간) / 왼쪽 본문(`◎`→소제목, `-`→목록, 그림+캡션) / 오른쪽 준비물·자료·유의점(☆★△를 `준비물` `자료` `유의점` 딱지로) |
| 9 | 평가 계획 | 관점·목표, 5수준 표, 평가 방법 |
| 10 | 연동 도구·링크 | 5절 |
| 11 | 내 수업 링크 | 5-3절 |
| 12 | 체험 게임 | 게임 제목·부제·포인트색, `체험 게임 열기` |
| 13 | 이전·다음 | 같은 학년 안에서, 학년 끝에서는 다음 학년 첫 차시 |

- 과정안 그림은 hwpx 안의 원본을 가로 960px jpg로 줄여 싣는다. AI 생성 삽화는 과정안 캡션에 `(AI 생성 삽화)` 표시가 이미 있어 그대로 드러난다.
- 인쇄하면 메뉴·단추·내 링크를 숨기고 과정안만 찍힌다(`@media print`).
- 개요의 `개발자` 칸은 **싣지 않는다**(`export_plans.py`의 `SHOW_DEV=False`). 9절 참고.

### 4-6. 연동 도구 모음 `tools/`

묶음(코딩·인공지능·데이터·제작·안전)별로 도구 카드. 카드마다 용도, 계정 조건, 보조 안내 링크, **이 도구를 쓰는 차시 칩**. 도구 준비(계정·학교망 허용·기기)를 학기 전에 한 번에 점검하는 쪽이다.

### 4-7. 체험 게임 목록 `play/`

예전 루트 허브를 옮긴 것이다. 학년별 카드(차시 칩·게임 제목·부제·포인트색). 개인정보 안내 한 줄 상시.

## 5. 연동 도구·링크 설계

### 5-1. 세 겹

| 겹 | 누가 거나 | 어디에 남나 | 누구에게 보이나 |
|---|---|---|---|
| ① 자동 도구 | 기계 — 과정안 본문에 도구 이름이 나오면 붙는다 | `_data/tools.json` | 모두 |
| ② 차시 추가 링크 | 연구진 — 차시에 꼭 필요한 특정 쪽(예: B19 비주얼 통계 「지역별 초등학생 수」, B11 라디오 블록 설명) | `_data/links.json`의 `extra` | 모두 |
| ③ 내 수업 링크 | 교사 개인 — 학급 패들렛, 엔트리 작품, 활동지 주소 | 그 교사 브라우저의 `localStorage` | 그 교사만 |

### 5-2. 자동 도구 — `tools.json`

```json
{"id": "createai", "name": "micro:bit CreateAI", "url": "https://createai.microbit.org/",
 "group": "인공지능", "use": "움직임 데이터로 동작 모델 학습·시험",
 "account": "필요 없음(크롬·엣지)", "match": ["CreateAI"],
```

### 5-3. 내 수업 링크

- 이름 + 주소 두 칸, `걸어 두기`. 목록에서 `빼기`.
- `https://`로 시작하는 주소만 받는다.

### 5-4. 링크 점검

체험 게임의 디자인 언어를 누리집에도 그대로 쓴다. 한 저장소가 한 얼굴을 갖게 한다.

|---|---|

| 학년 색 | 5학년 호박 `#F59E0B`, 6학년 파랑 `#3D5AFE` |

| 글자 | 본문 16px, 줄 간격 1.7, `word-break: keep-all` |

게임 쪽과 다른 점: 누리집 쪽은 **읽는 쪽**이므로 한 화면 250자 상한을 두지 않는다. 대신 목차 바로가기, 행 카드, 표로 훑어 읽기 쉽게 한다.

## 10. 배포와 운영

1. 작업은 `site` 가지(branch)에서 하고, 점검 0건이면 `main`에 합친다. `main`이 GitHub Pages로 나간다.
2. 합치기 전에 PR에서 Actions `감사`가 통과해야 한다.
3. 학기 운영 중 과정안이 바뀌면 3-2절 차례를 따른다. 누리집 바닥의 `과정안 기준일`(`site.json`의 `updated`)을 함께 바꾼다.
4. 저장소 크기: 과정안 그림 약 8MB, PDF 약 9MB. 그림은 960px jpg로 줄였고, 이 이상 커지면 PDF를 GitHub Releases로 옮긴다.
