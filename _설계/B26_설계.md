# B26 체험 설계 — 한 가지만 고쳐 다시

2026. 9. 17. 판정을 뒤집었다. 앞선 판정문은 9절에 남겨 둔다.
2026. 9. 27. 개정 과정안(손목 마이크로비트 손 씻기 코치)에 맞춰 카메라 판을 걷어 내고 다시 짰다. 맨 끝 절에 적는다.

## 0. 만들까 말까

**만든다.** 코치 2.0 고치기를 대신하지 않고, 실물로 고치기 **전**에 되풀이 한 바퀴를 3분에 여러 번 돌린다.

- **웹이 아니면 못 하는가.** 이 차시의 규칙은 **시험 방법을 그대로 두고 한 부분만 고쳐** 다시 시험하는 것이다.
  실물로는 샘플 녹화·재학습·MakeCode 내려받기까지 한 바퀴에 20분 넘게 걸려 한 번밖에 못 돈다.
  화면은 시험 기록을 잠가 두고, 고칠 부분 하나를 골라 다시 시험하는 바퀴를 몇 초에 돌린다.
- **값을 바꾸면 결과가 바뀌는가.** 고칠 부분(데이터·모델·사용 조건) 하나를 고르고 `다시 시험`을 누르면
  같은 시험 여섯 번의 결과가 눈앞에서 바뀐다. 바뀌기도 하고 안 바뀌기도 한다.

**여전히 만들지 않는 것.** 사용 조건 카드로 다른 친구가 코치를 써 보기(활동1), 도감 카드 쓰기(활동2),
샘플 녹화·재학습·밴드 보수(활동3), 코치 2.0 실제 시험(활동4), 알려진 한계 쓰기. 손목 마이크로비트와
CreateAI가 본론이다. 화면은 **원인 세 갈래 가운데 하나만 고치는 한 바퀴**만 맡는다.

---

## 1. 과정안 어디에 붙는가

- 블록 B26, 25~26차시. **활동2. 원인 가려 오류 도감 카드 만들기**를 마치고
  **활동3. 한 부분만 골라 고치기**로 들어가기 **직전** 3~5분.
- 도감 카드에 원인 하나를 적어 둔 학생이, 실물로 고치기 전에 "한 부분만 고치면 어디까지 달라지나"를
  몇 판 돌려 본다. 활동3·4를 대신하지 않는다. 화면에 `마이크로비트 코치로 다시 시험해요`를 상시로 둔다.
- 카메라·마이크를 쓰지 않는다.

---

## 2. 한 문장

**시험 기록은 잠가 둔 채** 데이터·모델·사용 조건 가운데 한 부분만 고치고 다시 시험하면,
같은 여섯 번의 결과가 어디서 달라지는지 본다.

---

## 3. 화면 (1화면, 위아래 두 칸)

| 칸 | 보이는 것 | 학생이 하는 것 |
|---|---|---|
| 위 `시험 기록`(자물쇠) | 사용 조건 카드 한 장, 기본 조건·카드 조건 × 세 동작 표(○·✕), `학습 데이터 · ○○ 샘플 N개`, 맞힌 수 `N / 6`, 남은 시험 | 읽는다. `다시 하기` `다음 판` |
| 아래 `고칠 부분 하나` | `데이터` `모델` `사용 조건`, `다시 시험` | 하나를 골라 다시 시험한다 |

- 위 칸은 처음부터 잠겨 있다. 시험 방법(여섯 번)은 어떤 조작으로도 바뀌지 않는다.
- 다시 시험하면 칸마다 `지난`(흐린 표시)과 `이번`을 나란히 둔다. 달라진 칸은 테두리가 굵어지고 한 번 뛴다.

### 게임 — `두 번 안에 여섯 번을 다 알아보게 하라`

- `다시 시험`은 **두 번까지**. 한 번에 **한 부분만** 고른다. 고친 것은 다음 시험에도 남는다(1.0 → 2.0 → 2.1).
- 셋에 한 판꼴로 원인이 두 갈래다. 그 판은 두 번 다 맞게 골라야 끝난다.
- 다 알아보면 `여섯 번을 다 알아봤어요`. 두 번을 다 쓰고도 남으면 `두 번을 다 썼어요 · 알려진 한계에 적어요`
  (과정안 활동4 `아직 못 알아보는 상황을 ‘알려진 한계’ 칸에 적기`로 잇는다). 나무라지 않는다.

**게임의 다섯 칸.** 목표(여섯 번을 다) · 실패(두 번을 다 쓸 수 있다) · 예상(고칠 부분 하나를 걸고 시험) ·
제약(한 번에 한 부분, 두 번까지, 시험 기록 잠김) · 되풀이(다음 판). 다섯을 채웠다.

## 4. 조작과 값

- 조절하는 값: **고칠 부분** 하나(데이터 / 모델 / 사용 조건).
- 판 뽑기(그 자리에서):
  - 사용 조건 카드: 다른 사람·왼손·빠르게·천천히·손등 착용 가운데 하나(과정안 활동1).
  - 숨은 원인: 데이터·모델·사용 조건 가운데 하나, 1/3 확률로 두 갈래. **화면에 적지 않는다.**
  - `데이터` 원인: 카드 조건의 시도가 빗나간다(네에 하나꼴로 한 동작은 알아봄). 그 조건 샘플은 **0개**로 보인다.
  - `모델` 원인: 두 동작(60%는 손바닥·손등)이 기본 조건에서도 카드 조건에서도 빗나간다.
  - `사용 조건` 원인: 카드 조건의 시도 가운데 한두 개가 빗나간다. 그 조건 샘플은 **3개**로 보인다.
  - 처음부터 다 알아보는 판, 직전 판과 같은 판은 다시 뽑는다.
- 근거는 화면에 있다. 과정안 활동2의 세 물음과 같다 — 기본 조건에서도 빗나갔나(모델), 그 조건 샘플이 몇 개였나(데이터), 둘 다 아니면(사용 조건).
- 판정: 칸마다 `고쳐야 할 부분들`이 있고, 그것이 모두 고쳐졌으면 알아본다.

```
needs[줄][동작] = []
모델 원인  → pair의 두 동작, 두 줄 모두 'model'
데이터 원인 → 카드 줄, dataKeep 말고 모두 'data'
사용 원인  → 카드 줄, useHit 동작 'use'
알아봄 = needs 가 모두 fixed 에 들어 있다
```

## 7. 만드는 방법

- 외부 라이브러리 없음. 저장 없음. 바닐라 JS, 인라인 SVG(○·✕ 기호, 자물쇠).
- ○는 채운 원, ✕는 빈 원에 가위표 — 색으로만 가르지 않는다.
- 표 여섯 칸은 처음 한 번만 짓고 안의 기호만 바꾼다.
- 두 번 눌림 막기: `retest()`는 버튼이 흐리면 되돌아간다. 고른 것은 시험 뒤 비운다.

### 앞선 판정문 (2026. 9. 11.)

> 만들지 않는다. B25와 같은 조작의 되풀이다.

되풀이인 것은 맞다. 그런데 **되풀이 그 자체가 이 차시의 알맹이**라는 것을 앞 판정이 놓쳤다.

## 개정 과정안 반영 (2026-09-27)

**판정: 재설계(틀은 유지, 대상·조작 교체).**

점검한 것
- 옛 판은 카메라 + 미니 이미지 모델(가·나·다 손 모양, k-NN)로 학습 예시를 더 담는 게임이었다. 개정안 B26은 **손목 마이크로비트·CreateAI 손 씻기 코치 2.0**이고, 이미지 분류가 나오지 않는다. 카메라 판을 두면 과정안에 없는 도구를 들여오는 셈이다(공통기준 11-1).
- 붙던 자리 "26차시 활동3 앞(입력·자료·안내 가운데 원인)" → 개정 **활동2. 원인 가려 오류 도감 카드 만들기** 뒤, **활동3. 한 부분만 골라 고치기** 앞. 원인 세 갈래는 과정안 말 그대로 **데이터·모델·사용 조건**.
- 사용 조건 카드 다섯 장(다른 사람·왼손·빠르게·천천히·손등 착용), 기본 조건과 따로 적기, 그 조건 샘플 수 세기, 시험 방법 그대로 두기를 화면이 그대로 따른다.

바꾼 것
- 카메라·그리기 칸·미니 모델·연습 모드·개인정보 문구를 걷어 냈다(쓰지 않으므로).
- 조작을 `가·나·다 담기`에서 **고칠 부분 하나 고르기(데이터·모델·사용 조건)**로 바꾸었다. 시험 칸 잠금, 지난·이번 나란히, 달라진 칸 뛰기, 횟수 제약(세 번 → 두 번)은 옛 판의 틀을 이었다.
- 부제 `시험 세 장은 그대로 둬요` → `시험 방법은 그대로 둬요`, 되짚기 `엔트리로 다시 시험해요` → `마이크로비트 코치로 다시 시험해요`. 허브 카드 부제는 `_tools/make_hub.py`로 다시 세워야 바뀐다.

검사(2026-09-27): `python _tools/run_all.py B26` — 문법·감사·헤드리스 모두 0건, **통과**.
