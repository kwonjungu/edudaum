# B25 체험 활동 설계 — 손목 동작 샘플 모아 견주기

- 경로: `B25/index.html` (단일 파일, 정적 호스팅, 서버·API 키·바깥 스크립트 없음)
- 다시 쓴 날: 2026. 10. 11. (지도안 검토반영본 `final2/B25.txt` 기준, 게임이 아니라 **체험 활동**으로)
- 센서: 태블릿 `devicemotion` 가속도. 지도안이 쓰는 감각(손목 마이크로비트의 x·y·z 움직임 그래프)을 흉내 낸다.
  센서가 없거나 권한을 거부하면 **연습 모드**(버튼으로 그래프 고르기)로 같은 순서를 밟는다.
- 앞선 판(같은 시험 데이터로 견주기 게임, 2026-09-27)은 맨 끝 절에 남긴다.

## 0. 지도안의 어느 활동을 웹으로 옮겼나

지도안 21~23차시의 활동 넷을 **그 순서대로** 한 화면에 옮겼다. 실물(손목 마이크로비트·CreateAI)로
하기 **앞**에, 또는 기기가 모자란 모둠이 **같은 절차를 겪는 자리**에 쓴다.

| 웹의 단계 | 지도안 문구(인용) |
|---|---|
| 1. 샘플 녹화 | 활동2 `동작 이름 세 개를 만들고 동작마다 샘플 3개만 녹화하기`, `그래프를 보고 잘못 녹화한 샘플은 지우고 다시 녹화하기` |
| 2. 시험(1회차) | 활동3 `녹화 샘플은 학습 데이터, 시험 담당의 새 시도는 시험 데이터로 나누기`, 활동4 `화면에 뜬 동작 이름과 확신 %를 시도마다 기록지에 적기`, `카드의 동작과 같으면 동그라미, 다르면 가위표로 적기` |
| 3. 예상 한 줄 | 활동5 `모든 모둠이 바꿀 조건은 샘플 수 하나(3개 → 8개)임을 확인하기`, `8개로 늘리면 결과가 어떻게 될지 예상 한 줄 쓰기` |
| 4. 샘플 8개로 다시 | 활동6 `같은 녹화 조건으로 동작마다 샘플 5개를 더해 8개 만들기`, `봉투에 넣어 둔 시험 방법 그대로 … 2회차 시험하기`, `‘샘플 3개’와 ‘샘플 8개’ 칸의 맞힌 수를 나란히 적기` |

- 동작 이름은 지도안 실습 안내 그대로 **손바닥 문지르기 · 손등 문지르기 · 손가락 문지르기**.
- 용어는 지도안 말만 쓴다: 샘플, 학습 데이터, 시험 데이터, 시험 순서 카드, 확신 %, 맞힌 수, 헷갈림 판.
- **대신하지 않는 것**: 활동1(동작 기준 정하기), 실제 마이크로비트 녹화와 CreateAI 학습, 칠판 결과 모음,
  활동7 MakeCode 코치. 화면에 `CreateAI로 다시 해 봐요`를 상시로 둔다.
- 지도안은 시험을 동작마다 다섯 번(15번) 한다. 화면은 한 줄에 다 보이게 **동작마다 두 번(6번)**으로 줄였다.

## 1. 한 문장

태블릿을 손목처럼 쥐고 세 동작의 샘플을 3개씩 모아 시험한 뒤, 샘플만 8개로 늘려 **같은 시험 데이터**로 다시 견준다.

## 2. 화면 (한 쪽, 위에서 아래로 네 단계)

|---|---|---|---|

| 1 샘플 녹화 | 동작 세 칸(칸마다 샘플 자리 3개와 작은 x·y·z 그래프), `녹화` | 동작 칸을 골라 `녹화` → 2초 동안 동작. 그래프를 보고 튀는 샘플은 눌러 지운다 | 세 동작 모두 3개 |

| 끝 | 기록지 두 칸 나란히, 예상과 몇 번 떨어졌는지, **활동지에 옮겨 적을 것** 한 줄 | 활동지에 옮겨 적는다 | `다시 하기` |

## 3. 조작과 값

### 3-1. 센서 붙이기 (공통기준 11-3)
- `DeviceMotionEvent.requestPermission`이 **있으면**(iOS): 머리에 `센서 켜기`. 누르면 권한 요청.
  허락 → 센서 모드. 거부·오류 → 연습 모드에 머문다(`센서를 못 켜서 연습 모드로 해요`).
- 없으면: 바로 `devicemotion`을 붙이고 1.5초 안에 값이 있는 이벤트가 오면 센서 모드. 오지 않으면(노트북) 연습 모드.
- 처음부터 연습 모드로 조작된다. 센서는 되면 저절로 붙는다(조작을 권한 버튼 뒤에 숨기지 않는다).
- `visibilitychange`(숨김)·`pagehide`에서 떼고, 다시 보이면 붙인다.

### 3-2. 녹화 한 번
- 센서 모드: `accelerationIncludingGravity` x·y·z를 9.8로 나눠 2초 동안 모은다. 시작 전 1초 `준비`, 녹화 중 남은 초.
- 연습 모드: `녹화`를 누르면 **그 동작의 그래프 세 장**이 뜬다(그 자리에서 만든 것, 한 장은 셋에 한 번꼴 움직임이 거의 없거나 축이 엉뚱한 튀는 그래프). 하나를 눌러 고른다 = 버튼으로 그래프 고르기.
- 샘플 자리를 누르면 그 샘플이 지워진다(지도안 `잘못 녹화한 샘플은 지우고 다시`).

### 3-3. 특징과 판정 (화면 안 미니 모델, 바깥 호출 없음)
- 특징 7개: 축별 평균 3(손 방향) · 축별 흔들림(표준편차) 3(움직이는 방향) · 평균선을 넘나든 횟수 1(빠르기).
  지도안 활동1의 기준 `손 방향·움직이는 방향·빠르기`와 같은 셋이다.
- 판정: 시험 시도와 샘플마다 거리를 재고, 동작마다 가장 가까운 거리 d를 잡는다. 예측 = d가 가장 작은 동작.
  확신 % = (1/d) 비율. 화면에는 `예측 동작 · 확신 %`만 보인다.
- 연습 모드의 시험 시도는 **시험 담당이 한 것처럼** 샘플과 조금 다른 버릇(기울기·빠르기 치우침)으로 만든다.
  손바닥·손가락 문지르기는 기울기·흔들림이 겹치게 만들어 샘플 3개에서는 헷갈릴 수 있게 둔다. 결과 수치는 미리 정하지 않는다.

### 3-4. 같은 시험 방법
- 시험 순서 카드 여섯 장(동작마다 둘)은 한 번 섞이면 그대로다. 2회차는 **1회차에 모은 그 여섯 시도**를 다시 판정한다.
  시험 시도는 샘플에 넣지 않는다(지도안 `시험 담당의 시도는 샘플로 녹화하지 않고`).
- 2회차 전에 바꿀 수 있는 것은 샘플 수 하나뿐이다. 1회차 샘플은 지울 수 없게 잠근다.

### 3-5. 결과 문구
- 예상과 2회차 맞힌 수: `짚은 대로 N번이에요` / `짚은 것보다 N번 더 알아봤어요` / `짚은 것보다 N번 덜 알아봤어요`.
- `맞았어요·틀렸어요·잘했어요`는 쓰지 않는다. 기록지 기호는 ○·✕(지도안 동그라미·가위표).
- 맞힌 수가 오르지 않아도 그대로 보인다(지도안 유의점 `오르지 않은 결과도 그대로 적게`).

### 3-6. 활동지에 옮겨 적을 것 (저장·전송 없음)
```
샘플 3개: 손바닥 a/2 · 손등 b/2 · 손가락 c/2 (모두 n/6)
샘플 8개: 손바닥 a/2 · 손등 b/2 · 손가락 c/2 (모두 n/6)
헷갈림: 손가락→손바닥 2번 …   (없으면 '헷갈림 없음')
```

## 5. 연습 모드
- 권한 거부·센서 없음 → 연습 모드. 상태 줄에 `연습 모드`라고 적는다. 같은 네 단계를 그대로 밟는다.
- "진짜와 같다"고 적지 않는다. 연습 모드 그래프는 화면이 만든 것이다.

## 6. 만드는 방법
- 바닐라 JS, 인라인 SVG 그래프(x 실선·y 긴 점선·z 짧은 점선 — 색만으로 가르지 않음). 저장 없음.
- 버튼은 대부분 JS로 만든다(감사기의 버튼 수 상한 14).
- 상태 `st = {mode, samples:[[],[],[]], cards, tries, r1, r2, guess, step}`.
